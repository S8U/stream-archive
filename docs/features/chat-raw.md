# 채팅 원본 보관

## 상태

- 구현 완료

## 목적

플랫폼에서 받은 채팅 응답을 가공하지 않고 동영상별 파일로 남긴다.
나중에 후원, 구독, 역할 같은 채팅 기능을 추가했을 때 지난 녹화도 원본을 다시 파싱해 채울 수 있게 하기 위함이다.

DB 컬럼이 아닌 파일에 두는 이유는 용량이다.
2026-10 실측 기준으로 치지직 채팅 원본은 메시지당 평균 약 1.1KB다.
DB에 넣으면 기존 채팅 테이블(약 2.3GB)의 7~8배가 되지만, 파일 전체를 gzip하면 원본의 약 16%로 줄어든다.

## 저장 위치

| 시점 | 파일 |
|---|---|
| 녹화 중 | `videos/{videoId}/chat-raw.jsonl` |
| 녹화 종료 후 | `videos/{videoId}/chat-raw.jsonl.gz` |

동영상을 삭제하면 동영상 디렉토리와 함께 지워진다.
삭제된 동영상의 채팅 행은 DB에 남지만 원본은 남지 않는다.

## 파일 형식

한 줄이 원본 메시지 하나인 JSONL이다.

```json
{"offsetMillis":12345,"receivedAt":"2026-10-14T20:00:12.345","format":"TEXT","payload":"{\"ver\":\"2\",\"cmd\":93101,...}"}
```

| 필드 | 설명 |
|---|---|
| `offsetMillis` | 녹화 시작 기준 수신 시각 (밀리초) |
| `receivedAt` | 서버 수신 시각 (서버 시간대 기준 ISO-8601) |
| `format` | `TEXT`는 받은 문자열 그대로, `BINARY`는 받은 바이트를 Base64로 인코딩 |
| `payload` | 원본 |

원본 메시지의 단위는 플랫폼마다 다르다.

| 플랫폼 | 단위 | 형식 |
|---|---|---|
| 치지직 | WebSocket 프레임 하나 (JSON) | `TEXT` |
| 트위치 | WebSocket 프레임 하나 (IRC 줄, 여러 줄일 수 있음) | `TEXT` |
| SOOP | WebSocket 프레임 하나 (바이너리 패킷) | `BINARY` |
| 유튜브 | `liveChatMessages.list` 응답 본문 하나 (JSON) | `TEXT` |

받은 프레임은 채팅 외 명령(핑, 접속 응답 등)까지 모두 남긴다.
보낸 프레임(접속 토큰 등)은 남기지 않는다.
WebSocket 제어 프레임(ping/pong)은 남기지 않는다.

## 동작

1. 채팅 수집을 시작하면 녹화별 기록기를 연다. 파일은 첫 메시지를 받을 때 만든다.
2. 받은 원본을 평문 JSONL에 줄마다 바로 이어 쓴다. 재연결해도 같은 파일에 이어 쓴다.
3. 녹화를 끝내면 채팅 수집을 멈춘 직후, 녹화 종료를 확정하기 전에 gzip으로 압축하고 평문을 지운다.

녹화 중에는 압축하지 않는다.
서버가 비정상 종료돼도 평문은 마지막 줄까지 읽을 수 있고, 주기적으로 압축하면 압축률이 떨어지기 때문이다.

압축을 녹화 종료 확정보다 먼저 하는 이유는 복구 때문이다.
압축 도중 서버가 꺼지면 녹화가 미종료로 남는다.
부팅 때 `RecordingStaleCleanupRunner`가 미종료 녹화의 종료를 다시 진행하면서 압축도 마친다.
압축은 임시 파일에 쓴 뒤 바꿔 넣으므로 깨진 압축 파일이 남지 않는다.

원본 기록이나 압축이 실패해도 채팅 수집과 녹화 종료는 계속한다.
기록에 실패하면 그 녹화의 원본 기록만 멈춘다.
재연결할 때 기록기를 다시 열지 않는다. 종료와 재연결이 겹쳐도 압축을 마친 뒤에 평문이 새로 생기지 않게 하기 위함이다.

유튜브는 응답 본문을 파싱하기 전에 원본으로 넘긴다. 응답 형식이 바뀌어 파싱이 깨져도 원본은 남는다.

## 관련 코드

- `PlatformChatWebSocketHandler`: 받은 프레임을 원본으로 넘긴 뒤 플랫폼별 처리를 맡긴다.
- `YoutubeChatCollectionSession`: 조회한 응답 본문을 원본으로 넘긴다.
- `RecordingChatRawWriteManager`: 녹화별 원본 파일에 이어 쓴다.
- `VideoChatRawCompressService`: 평문 원본을 gzip으로 압축한다.
- `RecordingEndUseCase`: 채팅 수집을 멈춘 뒤 압축을 호출한다.
